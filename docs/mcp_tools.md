# Daedalus MCP Tools

An MCP server (`mcp_server/server.py`) exposing tools for Claude to query and
explain what the Daedalus event detector and options executor are doing.
Built for live interactive questioning during the hackathon demo.

**Every tool's return payload includes an `is_mocked` field.** Check it
before treating any tool's output as live data — this doc explains why each
one is `true` or `false`, but the field itself is the source of truth even
if this doc goes stale.

## Real vs. mocked, at a glance

| Tool | `is_mocked` | Data source |
|---|---|---|
| `get_open_positions` | `false` | Live Alpaca API call (paper account) |
| `get_recent_signals` | `false` | `data/events.jsonl` (written by `agent/event_detector.py`) |
| `explain_trade_decision` | `false` | `data/trades.jsonl` (written by `agent/options_executor.py`) |
| `get_health_status` | `false` | Live Alpaca `get_account()` call + env var presence checks |
| `get_lessons_learned` | `false` | `docs/lessons_learned.json` (hand-maintained) |
| `get_market_regime` | `false` | Live SPY daily bars via Alpaca, heuristic classifier |
| `run_bear_case` | `false` (context) | Real trade/event context + a static risk-factor checklist — **the narrative argument itself is not generated by this tool**; the calling model synthesizes it |
| `get_icarus_signals` | **`true`** | Fully fabricated. Icarus is a separate production system not in this repo |

## Prerequisites for real data to actually be present

`get_recent_signals` and `explain_trade_decision` read local append-only
logs that only exist once the corresponding script has actually run:

```
python -m agent.event_detector --once          # populates data/events.jsonl
python -m agent.options_executor --once --dry-run   # populates data/trades.jsonl
```

A dry-run trade record is fully real (real event, real live quotes, real
sizing math) except that no order was actually submitted — the record's
`dry_run: true` field makes this explicit. If neither log has any history
yet, both tools return `found: false` / an empty list with a note telling
you which script to run, rather than fabricating something to show.

## Running the server

```bash
# Directly, for local testing:
python -m mcp_server.server

# Via the MCP CLI:
mcp dev mcp_server/server.py
```

The server loads `.env` from the repo root explicitly (not via CWD-relative
search), so it works correctly when spawned by Claude Desktop from a
different working directory. `paper=True` is hardcoded for the Alpaca
client, same rule as `agent/options_executor.py` — it is never configurable
via `ALPACA_BASE_URL`.

### Claude Desktop config

Add to `claude_desktop_config.json` (adjust the path to your checkout):

```json
{
  "mcpServers": {
    "daedalus": {
      "command": "C:\\Users\\Admin\\alpaca-hackathon-agent\\.venv\\Scripts\\python.exe",
      "args": ["-m", "mcp_server.server"],
      "cwd": "C:\\Users\\Admin\\alpaca-hackathon-agent"
    }
  }
}
```

Using the venv's `python.exe` directly (rather than relying on a shell to
activate the environment) avoids dependency-resolution issues since Claude
Desktop spawns the process directly, not through a shell profile.

## Tool reference

### `get_market_regime()`
- **Inputs:** none
- **Output:** `{is_mocked: false, method, symbol, regime, basis: {lookback_trading_days, realized_vol_annualized_pct, net_move_pct, up_days, down_days, thresholds}}`
- `regime` is one of `trending_up` / `trending_down` / `choppy` / `high_vol` / `unknown`
- **Real, but a crude heuristic** — computed from the last 10 SPY daily bars (realized volatility + directional consistency vs. configurable thresholds in `mcp_server/logic.py`). Not a sophisticated regime model; labeled as such in `method`.

### `get_open_positions()`
- **Inputs:** none
- **Output:** `{is_mocked: false, count, positions: [{symbol, qty, side, avg_entry_price, current_price, market_value, unrealized_pl, unrealized_plpc}]}`
- **Real.** Live `alpaca-py` `get_all_positions()` call against the paper account. Will be an empty list if nothing is currently open.

### `get_recent_signals(n=10)`
- **Inputs:** `n` (int, default 10) — max number of recent events to return
- **Output:** `{is_mocked: false, source, count, signals: [Event...], note}`
- **Real.** Reads `data/events.jsonl`, newest first. `note` explains how to populate this if it's empty.

### `run_bear_case(ticker=None, event_type=None)`
- **Inputs:** `ticker` and/or `event_type` (both optional) — used to find the most relevant recent trade/event context; falls back to the most recent decision overall
- **Output:** `{is_mocked: false, reasoning_aid: true, note, context: <real trade record or null>, risk_factor_checklist: [str, ...]}`
- **Hybrid, by design.** `context` is a real record from `data/trades.jsonl`. `risk_factor_checklist` is a static list of generic risk considerations (IV crush, thesis-already-priced-in, reversal risk, macro correlation, confidence miscalibration, liquidity). **This tool does not call an LLM to generate a finished argument** — it hands the calling model real material to reason over. The actual narrative bear case is synthesized by Claude when this tool is used, not fabricated in advance and returned as canned text.

### `get_lessons_learned()`
- **Inputs:** none
- **Output:** `{is_mocked: false, source, count, lessons: [{id, date, component, title, summary, impact}, ...]}`
- **Real project history.** Reads `docs/lessons_learned.json`, which you hand-maintain — nothing here is hardcoded in Python. Currently seeded with the 6 calibration fixes from this week (word-boundary matching, domain-aware lexicons, consensus-based confidence, macro-proxy ticker, DTE server-side filtering, position-sizing/budget gate).

### `get_health_status()`
- **Inputs:** none
- **Output:** `{is_mocked: false, alpaca: {api_key_configured, secret_key_configured, reachable, error, detail}, tavily: {api_key_configured, note}, anthropic: {api_key_configured}}`
- **Real, with one asymmetry:** Alpaca gets a genuine live reachability check (`get_account()`); Tavily gets a **key-presence check only** — no live search is fired, specifically to avoid burning API quota if this tool gets called repeatedly during the demo.

### `get_icarus_signals()`
- **Inputs:** none
- **Output:** `{is_mocked: true, note, signals: [{ticker, signal, fundamental_stress, sentiment_stress, reasoning}, ...]}`
- **Fully mocked.** Icarus is a separate production system, not included in this repo per the project's scope boundary. Every field is fabricated to illustrate the payload shape a live integration would return. `reasoning` fields are explicitly tagged `[ILLUSTRATIVE]` as a second layer of labeling beyond `is_mocked`.

### `explain_trade_decision(ticker=None, order_id=None)`
- **Inputs:** `ticker` or `order_id` (both optional) — if neither is given, returns the single most recent decision of any kind
- **Output:** `{is_mocked: false, found: bool, record?: {event, decision_mode, decision_reason, traded, detail, order_id, dry_run, extra, timestamp}, note?}`
- **Real, flagship tool.** Reads `data/trades.jsonl`. `record.extra` carries structured sizing math (equity, budget, ask/combined ask, qty, strike, expiration, underlying move %) so the numbers are exact, not re-parsed from a log string. `decision_mode` is one of `no_trade` / `directional_call` / `directional_put` / `straddle`; a budget-insufficient outcome is `traded: false` with `detail` starting `"SKIPPED: ..."`, distinct from a `decision_reason` that never qualified in the first place.
